Add a saved-carts endpoint so shoppers can park a cart and restore it on any device

New POST /carts/{id}/save and GET /saved-carts on shop-api, backed by a new saved_carts table. Prices re-check on restore. Decide how long saved carts live.

shop-apinew endpoint1 tablemigration

Context

Carts live in Redis for 24 hours and are tied to one session, so a shopper who switches devices starts over.
services/shop/cart/store.go:40
func (s *Store) Put(ctx context.Context, c Cart) error {	return s.redis.Set(ctx, "cart:"+c.SessionID, c.JSON(), 24*time.Hour).Err()}

Flow

Save copies the Redis cart into Postgres under the account; restore re-prices each line before it becomes the live cart.

Everything blue is new. Restore re-prices before writing the live cart.

Schema

One new table, one row per saved cart, lines as JSON.

02Save + restore handlers

Two handlers; restore re-prices through the pricing service and drops lines that no longer exist.
services/shop/cart/saved.go
  • Save(ctx, cartID): ownership check, insert row.
  • Restore(ctx, savedID): re-price, write the live cart.

func Restore(ctx, savedID) (Cart, error) {	saved := db.Get(savedID)            // 404 when missing or expired	quotes := pricing.Quote(saved.Lines)	lines := keep(saved.Lines, quotes)  // drop discontinued SKUs, take new prices	return store.Put(Cart{Lines: lines})}

Price drift

Restored carts always show today's price; the saved price is never honoured.
