# Components

## Component table {#table .open}
Write the left column in plan.md; the renderer produces the right. Full syntax: `l3/l3-plan-render/CONTRACT.md`.

| Component | Write in .md | Renders as | Notes |
|---|---|---|---|
| Header | front matter: `title`, `contract`, `type`, `eyebrow`, `h1`, `summary`, `chips` (`\|`-separated, first highlighted), `tabs` | page head + chips | `title` and `contract` are required. Docs may add `doc`, `skill`, `status`. |
| Tabs | `# Plan`, `# Open questions`, `# Testing`, `# Challenging the design` … (H1); order from front matter `tabs:` | tab bar + one panel per H1 | `#<panel>` deep-links a tab. Tabs holding questions or challenges show an open-count badge. No H1 = one untabbed panel. |
| Collapsible headers | `## 03 Title {#p-03}`; the first paragraph under it is the gist; `{.open}` starts it expanded | `<details>` fold whose gist hides when open | Every H2 folds. A leading two-digit number renders as the fold number. Each panel with folds gets an Expand all button; `#p-03` opens that fold. |
| Charts | ```` ```flow ```` or ```` ```erd ```` fence holding the l1 JSON spec, optional `"caption"` key | inline SVG figure(s) from l1-flow-svg / l1-erd-svg, CSS inlined once per page | A before/after flow spec renders as two figures. Every node carries `data-node` + `data-md` (the line of its `"id"`), so it can be commented on. |
| Q/A boxes | ```` ```question q4 ```` with `title:`, `context:`, then `- value* Label — consequence` lines (`*` = recommended; no options = free text) | answer card: radio options + textarea | Saves to `answers.q4` in the state file; shows the agent's `review` and `applied` notes. "Copy answers as text" covers all cards. |
| Challenge cards | ```` ```challenge c1 ```` with `title:` (the claim), then the argument as markdown | claim + argument + status select + reply | Same storage and review flow as Q/A boxes (`challenges.c1`). |
| Code + locator | ```` ```go path/x.go:212 ```` | locator line + code block | Real code, quoted from the file. Each line carries its own `data-md`. |
| Before / after pair | ```` ```go path:212 before [bug] ```` immediately followed by ```` ```go path:212 after ```` | two blocks, changed lines auto-marked | difflib marks the lines: after = green; before = red with `bug`, otherwise violet. A lone `before` fence is today's code with no marks. |
| Pseudo-code | ```` ```pseudo-go ```` (any `pseudo-<lang>`) | code block tagged pseudo | Logic that doesn't fit in a chart's boxes. |
| Files list | ```` ```files ````: a path line, then `- change` lines | file cards, one line per change | Work folds. |
| Ledger | ```` ```ledger Today: prorated ```` rows `name \| formula \| value`; `!` prefix = total/bug, `=` = total/ok | named-step math table | Consecutive ledger fences sit side by side. Money, rates, dates. |
| Callouts | `> [!bug] Title`, `> [!ok]`, `> [!note]`, `> [!warn]` | coloured callout box | Prod errors, constraints. |
| Check list | `- [ ] item` list items | checkbox list | Verify sections. |
| Tables | GFM table | scrolling table | Test matrices, comparisons. |
| html-block | ```` ```html-block ```` holding raw HTML | inserted inline in a wrapper that carries `data-md` | For one-off visuals. `<script>`, `on*` attributes and `javascript:` URLs are stripped. A plain ```` ```html ```` fence still shows HTML as code. Reused a lot? Promote it to a component (an L3 change). |
| Comments + copy to Claude | nothing | select text or click a chart node → comment popover; open comments show as margin pins | Saves to `comments` in the state file. Copy one or "Copy all open" gives `plan.md:42-47 (node x)` + quote + comment. |
