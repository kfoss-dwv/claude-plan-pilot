## Where to start {#start .open}
Read `OVERVIEW.md` for the level flow and file tree, `COMPONENTS_AVAILABLE.md` for what a plan.md can contain.

- `OVERVIEW.md`: level + script flow chart, then the repo file tree.
- `COMPONENTS_AVAILABLE.md`: every markdown construct the renderer knows. Generated by `render.py components --write`; never edit it by hand.
- `levels/lN/<skill>/<skill>.md`: what the skill does now. `<skill>-init.md`: the first build, a record. `<skill>-update-<slug>.md`: one plan per later change.

## Browse them {#browse}
Render one file, or serve the whole folder with an index page.

```bash
python3 l3/l3-plan-render/scripts/render.py docs/OVERVIEW.md      # -> docs/OVERVIEW.html
python3 l3/l3-plan-render/scripts/serve.py start docs/            # index of every doc, live
```

Rendered `.html` and `.state.json` files stay local (gitignored).

## Rules {#rules}
Docs change with the code they describe; `.cursor/BUGBOT.md` checks it on every PR.

- A change to `lN/<skill>/` updates `docs/levels/lN/<skill>/<skill>.md` in the same PR.
- `<skill>-init.md` and landed `<skill>-update-<slug>.md` files are history: never edited after they land. An update doc flips to `status: landed` and `<skill>.md` is updated in the same PR.
- Every doc is contract format with `contract:` equal to `l3/l3-plan-render/CONTRACT.md`. No raw HTML outside an `html-block` fence.

## Forking {#fork}
L1 and L2 are the customization surface; the defaults here are one person's preferences.

1. Fork the repo, then rename the marketplace in `.claude-plugin/marketplace.json` (two marketplaces with one name clash).
2. Develop with `claude --plugin-dir .`; install from your fork with `/plugin marketplace add <you>/claude-plan-pilot`.
3. Swap adapters under `l2/` or drawing styles under `l1/` freely. Leave `l3/` alone unless you want to own the renderer.
4. Pull updates with `git merge upstream/main`. A bumped `contract:` means an L3 change that may need your L2 edits updated.
